# Архитектура Legalizer Russian

## Задача

Legalizer Russian проверяет и редактирует юридические и официально-деловые документы, сохраняя профессиональную читаемость, терминологическую стабильность и жанровую структуру.

Он не наследует автоматически стилистические приоритеты Humanizer Russian. Обычная редакторская эвристика может быть полезна, нейтральна или вредна для юридического документа в зависимости от жанра.

## Сборка активного ruleset

Итоговый набор правил вычисляется в таком порядке:

1. `core` — инварианты смысла, нормы языка и source governance;
2. базовые legal/document правила;
3. профиль документа;
4. пользовательские overrides;
5. фильтр по юрисдикции и дате документа;
6. разрешение конфликтов.

Профиль может:

- `enable` — включить правило;
- `disable` — отключить правило;
- `downgrade` — снизить severity;
- `upgrade` — повысить severity при наличии достаточного основания;
- `override` — заменить параметры правила для данного профиля;
- `protect` — защитить конструкцию от общего редакторского правила.

## Главное правило конфликтов

Специализированное правило не побеждает общее только потому, что оно специализированное. Resolver учитывает:

1. применимость источника;
2. статус источника;
3. жанр;
4. дату действия;
5. специфичность scope;
6. confidence;
7. явный project override.

Нормативная или методическая рекомендация не превращается в обязательную норму через resolver.

## Пример конфликта

Обычный редактор может считать повтор слова стилистическим дефектом. В договоре введённые термины `Заказчик` и `Исполнитель` должны повторяться стабильно.

Поэтому `contractual` защищает `defined_term_consistency` и отключает generic synonymization для защищённых терминов, но не отменяет проверку бессмысленного повтора обычных слов.

## Профили

- `official-admin`
- `normative`
- `normative/legislation`
- `contractual`
- `legal-procedural`

Профили вложенные: `normative/legislation` наследует `normative`, затем добавляет законодательные правила.

## Severity

- `HARD_GATE` — механически доказуемая ошибка структуры/ссылки/формального требования с высокой уверенностью;
- `REVIEW` — вероятная юридическая, композиционная или терминологическая проблема, требующая контекста;
- `STYLE_WARNING` — регистровая/стилистическая эвристика;
- `INFO` — объяснение или рекомендация без утверждения об ошибке;
- `PASS` используется только в evals.

## Автоматическая правка

Автоправка допустима только если семантический риск практически отсутствует. Не делать автоматически:

- замену юридического термина;
- перенос условия или исключения;
- изменение модальности обязанности/права/запрета;
- перестройку обязательства;
- изменение перекрёстной ссылки;
- добавление/удаление определения;
- разбиение юридически значимого предложения, если меняется scope зависимых частей.

## Source-aware execution

Каждое правило может иметь:

```yaml
jurisdiction: RU
effective_from: 2025-08-18
effective_to: null
source_status: CURRENT_NORM
```

`PENDING_CHANGE` никогда не активируется как действующая норма до наступления и подтверждения `effective_from`.
