# Rules extracted from public legal/document sources

Первая выборка. Каждое правило сохраняет scope и статус источника.

## DOC-M01 — тип документа зависит от функции

Source locator: `DOC-ROSARCHIVE-71`, п. 2.1; подтверждено `DOC-ROSARCHIVE-199`, 3.3.1  
Scope: `official-admin`, государственные органы/МСУ; вне этого scope только проектная эвристика  
Basis: `SOURCE_DIRECT`  
Level: document  
Norm status: `CURRENT_NORM` для исходной области  
Confidence: high

Вид документа должен соответствовать полномочию, функции, порядку разрешения вопроса и характеру взаимодействия. Перед языковой редактурой классифицировать функцию документа, затем жанр.

Не утверждать, что частная компания обязана использовать тот же набор видов документов, что государственный орган.

## DOC-M02 — обязательные реквизиты должны переживать электронное представление

Source locator: `DOC-ROSARCHIVE-199`, 3.3.1  
Scope: `official-admin`, электронные документы в указанной источником области  
Basis: `SOURCE_DIRECT`  
Level: document/format  
Norm status: `METHODICAL`  
Confidence: high

При визуализации электронного документа и воспроизведении его на бумаге должны сохраняться реквизиты, обязательные для соответствующего вида документа.

## DOC-M03 — область применения инструкции должна быть явной

Source locator: `DOC-ROSARCHIVE-199`, 3.1  
Scope: `normative`, instruction/policy  
Basis: `SOURCE_DIRECT`  
Level: document  
Norm status: `METHODICAL`  
Confidence: high

В общих положениях инструкции рекомендуется указывать назначение, область применения, правовые основания разработки и порядок применения. Диагностировать, можно ли понять: зачем создан документ, на кого/что он распространяется, на каком основании действует и как применяется.

Не требовать отдельный раздел с точным названием `Общие положения`, если жанр решает задачу иначе.

## DOC-M04 — специальные термины должны быть определены однозначно

Source locator: `DOC-ROSARCHIVE-199`, 3.2  
Scope: `normative`, особенно инструкции  
Basis: `SOURCE_DIRECT`  
Level: document/term  
Norm status: `METHODICAL`  
Confidence: high

Если термин получает специальное значение, его определение должно быть найдено до систематического использования или явно доступно читателю.

Не создавать терминологический раздел в любом коротком документе без специальных терминов.

## DOC-M05 — сокращённое наименование вводится после полного

Source locator: `DOC-ROSARCHIVE-199`, 3.2  
Scope: `normative`, `official-admin`; безопасная эвристика и для других профессиональных документов  
Basis: `SOURCE_DIRECT` + `PROJECT_DERIVED`  
Level: term/document  
Norm status: `METHODICAL`  
Confidence: high

При небольшом числе многословных наименований источник предлагает после первого полного наименования вводить сокращённое: `(далее — X)`.

Механические кандидаты:

- `X` используется до конструкции `далее — X`;
- один объект получает несколько конкурирующих сокращённых наименований;
- одно сокращение введено для разных объектов.

Ориентир источника `3–5` многословных наименований не является универсальной числовой нормой любого документа.

## DOC-N01 — преамбула законопроекта не является контейнером норм

Source locator: `DOC-DUMA-LEGALTECH-2021`, гл. 1, п. 2  
Scope: `normative/legislation`  
Basis: `SOURCE_DIRECT`  
Level: document/section  
Norm status: `METHODICAL`  
Confidence: high

Преамбула законопроекта необязательна и определяет цели и задачи. Она не содержит самостоятельных нормативных предписаний, легальных дефиниций и предмета регулирования; не нумеруется и не делится на статьи.

Не переносить это правило на договорную преамбулу.

## DOC-N02 — структурная иерархия законопроекта не произвольна

Source locator: `DOC-DUMA-LEGALTECH-2021`, гл. 1, п. 3  
Scope: `normative/legislation`  
Basis: `SOURCE_DIRECT`  
Level: document/structure  
Norm status: `METHODICAL`  
Confidence: high

Источник задаёт нисходящую систему крупных структурных единиц: часть → раздел → подраздел → глава → параграф → статья и отдельно предупреждает о некоторых недопустимых пропусках уровней.

Не использовать эту иерархию для договоров, инструкций компании или процессуальных документов.

## DOC-N03 — ссылка должна выполнять функцию

Source locator: `DOC-DUMA-LEGALTECH-2021`, гл. 2, п. 17  
Scope: `normative/legislation`  
Basis: `SOURCE_DIRECT`  
Level: sentence/document  
Norm status: `METHODICAL`  
Confidence: high

Ссылки на другие статьи или законодательные акты применяются, когда необходимо показать взаимную связь норм, пояснить правовое положение или избежать повторений. Ссылка без понятной функции — кандидат на проверку, а не автоматическая ошибка.

## DOC-N04 — внутренние ссылки должны разрешаться

Source locator: `DOC-DUMA-LEGALTECH-2021`, гл. 2, пп. 17–30  
Scope: `normative`; `PROJECT_DERIVED` безопасно расширяется на договоры/политики  
Basis: `PROJECT_DERIVED`  
Level: document  
Norm status: `PROJECT_DERIVED`  
Confidence: high

Ссылка вида `пункт 4.2`, `приложение 3`, `настоящая статья` должна вести к существующей и однозначно определимой структурной единице. Неразрешимая внутренняя ссылка может быть `HARD_GATE` только при высокой уверенности parser-а.

## DOC-P01 — будущую норму нельзя применять как действующую

Source locator: `DOC-ROSARCHIVE-91-2026`; статус проверен 2026-08-28  
Scope: all legal/document linting  
Basis: `PROJECT_DERIVED`  
Level: source governance  
Norm status: `PROJECT_DERIVED`  
Confidence: high

Для нормативных источников хранить отдельные даты публикации/регистрации/вступления в силу. Rule engine фильтрует правила по `effective_from`, `effective_to`, jurisdiction и document date.

## DOC-P02 — профессиональный повтор не равен стилистической ошибке

Source locator: необходимость однозначной терминологии в `DOC-ROSARCHIVE-199`, 3.2; усилено книжным корпусом  
Scope: professional documents  
Basis: `PROJECT_REFINED`  
Level: term/document  
Norm status: `PROJECT_DERIVED`  
Confidence: high

Не применять общий механизм устранения повторов к введённым терминам и сокращённым наименованиям без проверки референта. Правило не оправдывает бессмысленный повтор обычных слов.
