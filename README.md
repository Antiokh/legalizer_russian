# legalizer_russian

Профессиональный русскоязычный редактор и линтер для юридических и официально-деловых документов.

Проект вырос из экспериментального legal-document слоя `Antiokh/humanizer_russian` и вынесен отдельно, потому что профессиональная юридическая читаемость местами требует правил, прямо противоположных обычной редакторской «естественности»: стабильного повтора терминов, допустимых клише, формальной модальности и жанрово-зависимой композиции.

## Принцип

Сначала определить тип документа и применимую систему источников, затем собрать активный набор правил. Правила могут включать, отключать, понижать или переопределять другие правила в зависимости от профиля.

## Профили

- `official-admin` — общий административно-канцелярский профиль;
- `official-admin/letter` — служебные и деловые письма;
- `official-admin/order` — приказы и распорядительные документы;
- `official-admin/act` — акты;
- `normative` — положения, правила, инструкции, регламенты, локальные нормативные акты;
- `normative/legislation` — законопроектная юридическая техника;
- `contractual` — договоры, соглашения, приложения;
- `legal-procedural` — претензии, иски, отзывы, ходатайства и другие процессуальные документы.

## Быстрый запуск

```bash
python -m pip install '.[dev]'
legalizer doctor
legalizer resolve --profile contractual
legalizer check contract.md --profile contractual
legalizer check order.md --profile official-admin/order
legalizer protect order.md --profile official-admin/order --json
legalizer check policy.md --profile normative --date 2026-08-29 --json
legalizer sources --date 2026-08-29
```

`doctor` проверяет связность профилей, source registry и runtime implementations. `protect` возвращает точные позиции фрагментов, которые профиль запрещает обычному редактору синонимизировать или упрощать. Сейчас механически локализуются введённые термины и инфинитивные действия в явно распознанной распорядительной части приказа; остальные классы защиты остаются явно перечислены в `unresolved_classes`, пока для них нет надёжного локатора.

Коды выхода `check`:

- `0` — находок нет;
- `1` — есть `REVIEW` / предупреждения;
- `2` — есть `HARD_GATE`;
- `3` — ошибка конфигурации, файла или аргументов.

Первый механический runtime включает:

- resolver наследования профилей и overrides;
- исполняемый `protect` / `disable_for_protected_spans` для интеграции с обычными редакторами;
- registry линтеров вместо profile-specific `if` в engine;
- фильтрацию правил по юрисдикции, статусу и дате источника;
- `DOC-M05`: использование определённого термина до введения и повторное введение alias;
- `DOC-N01`: нормативное предписание или дефиниция внутри явно размеченной преамбулы законопроекта;
- `DOC-N02`: раздел/подраздел без глав в законодательном профиле;
- `DOC-N04`: high-confidence внутренние ссылки на отсутствующие пункты, статьи и приложения;
- `DOC-P01`: проверку применимости источников активного ruleset;
- `LDB-009`: неопределённые сроки вроде «в ближайшее время» как `REVIEW`, без выдумывания даты;
- `LDB-012`: узкий `REVIEW`-сигнал на потенциально двусмысленное нанизывание творительных форм после номинализации;
- `ADM-ORDER-001`: нумерованный распорядительный пункт после явного `ПРИКАЗЫВАЮ` без инфинитивного действия.

Механические линтеры намеренно консервативны: если ссылка может быть внешней, термин — обычным словом, а синтаксическое прикрепление нельзя доказать без контекста, Legalizer не делает жёсткого вывода. Правило порядка слов теперь опирается на тему/рему, а не на `SVO required`; длинное профессиональное предложение не считается дефектом только по длине. Жанровые правила исполняются только через resolver: например, инфинитив приказа защищается в `official-admin/order`, но не навязывается письму или акту.

## Архитектура

```text
legalizer/            Python runtime, registry, protection API и CLI
core/                 схема правил и реестр источников
profiles/             включение/отключение/переопределение правил по жанрам
rules/                атомарные правила
references/           компактный рабочий контекст
studies/              исследования нормативных источников и книг
evals/                собственные исследовательские тестовые случаи
tests/                исполняемые runtime-тесты
docs/                 архитектура, источники и политика проекта
```

## Приоритет источников

В пределах одной применимой юрисдикции и даты:

1. действующая обязательная норма;
2. применимый действующий национальный стандарт;
3. официальные методические рекомендации;
4. специальная литература по юридическому письму и делопроизводству;
5. проектная эвристика.

Статус источника всегда хранится отдельно от силы конкретного правила. Опубликованное, но ещё не вступившее в силу изменение не считается действующей нормой.

## Текущий статус

Миграция юридического слоя из `humanizer_russian` PR #80 завершена: Legalizer является отдельным source of truth. Публичная нормативная база и первый корпус учебников перенесены; полные тексты книг и ГОСТов в репозиторий не копируются — сохраняются библиография, source locators, извлечённые правила, исключения и собственные evals.
